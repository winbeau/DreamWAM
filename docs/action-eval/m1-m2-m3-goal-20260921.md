## Frozen first-stage control

[`m1-fixed-m2-m3.json`](../../configs/sparse/m1-fixed-m2-m3.json) freezes M2 to
current first-layer AV plus backward VV support, context/guidance weights 1,
support seed ratio 0.1 and balanced frame quotas. M3 is Dense step 0, Sparse
step 5, feature Reuse at all remaining steps. All ten action updates remain.
These are executable controls, not claims of optimality or proven importance.

M1 changes only Q and KV ratios between chunks. Initial levels are Q/KV
10%/25%, 20%/50%, 30%/75%. These are **uncalibrated development choices**.
The controller sees current raw RGB from both cameras, eight-dimensional robot
proprioception and committed past observation summaries. It decides before text
encoding, VAE and denoising. No outcome, privileged state, instruction embedding,
attention, denoising latent or teacher prediction enters the decision.

RGB summaries are 32-square BOX thumbnails. Change uses the 90th percentile of
per-pixel mean absolute RGB change. Additional features are translation distance,
SO(3) orientation distance, two-finger displacement, and image/translation
deviation from the preceding two-observation linear trend. The maximum normalized
feature selects a band, thresholds 0.5/1.5. Scales and units are explicit in JSON;
they are not calibrated error bounds. Bootstrap uses high budget, upgrades are
immediate, and each one-level downgrade requires two lower-score observations.
History commits only after valid actions; episode reset discards it.

The scientific hypothesis is that these observable changes help predict
sparsification sensitivity. They do **not** establish semantic task phases,
contact detection, uncertainty calibration or safe control. Fixed-level controls
extract the same observation features and differ only in budget decisions.
