# 新版 M1–M3 图怎么读

桌面目录是 `DreamWAM-M123-20260921/M1-total-budget-v2/`。
先打开 `read-this-first-kv75/index.html`，点击某个 chunk 的“四格导读”。
`read-this-first/index.html` 是读取预算随档位变化的对照。
其余 capture、旧版导读和日志目录保留复核证据。

**一个文件只对应一个 chunk、一个去噪步。九格图再指定一个 transformer 层。**
例如 `s03-l00-rows-and-columns.png` 是第 3 个去噪步、第 0 层。
图里的三行不是第 0/1/2 个去噪步。

## 先看四格图

| 位置 | 看什么 |
|---|---|
| 左上 ① | 当前真实 RGB；格子里的数字是视觉 token ID |
| 右上 ② | AV：动作 token 对视觉位置的注意力；圆圈标出 AV 种子 |
| 左下 ③ | VV：这些 AV 种子又关联哪些视觉位置 |
| 右下 ④ | 实际执行：蓝色表示读取，绿色 `+` 表示本步重算，灰色表示没读 |

**四格都对应同一张真实首帧**。对照相同格子位置，就能从原图一路读到计算。
每格左半是外部相机，右半是腕部相机；不是两张时间不同的照片。

## 再看九格图

| 大图的行 | 左列：路由 AV | 中列：实际执行 AV | 右列：VV 支持 |
|---|---|---|---|
| 第 1 行 | 当前首帧的位置 | 当前首帧的位置 | 当前首帧的位置 |
| 第 2 行 | 未来 latent 1 | 未来 latent 1 | 未来 latent 1 |
| 第 3 行 | 未来 latent 2 | 未来 latent 2 | 未来 latent 2 |

横着看：同一帧的三种指标。竖着看：同一指标在三个 latent 帧上的分布。
后两行没有真实未来 RGB，不能当成模型收到的未来照片。
左列使用第 0 层的路由探针，中列使用文件名指定层实际读到的 K/V。
Reuse 步没有重新运行路由探针时，左右两列会明确写“本步没有运行路由探针”。

每个小图内部的横坐标 0–13、纵坐标 0–6，才是 **patch 的空间位置**。
编号公式为 `token ID = latent 帧号 × 98 + patch 行号 × 14 + patch 列号`。
例如内部第 4 行、第 7 列，对应首帧 ID 63、未来帧 ID 161 或 259。
它们共享名义空间位置，但不是同一个时间 token。格子约为模型输入中的
32×32 像素区域；VAE 感受野有重叠，不能解释成独立像素的因果归因。

## 颜色和符号

- 热力图的黑色/深紫色：有效位置的数值低。原始 RGB 里的黑色只是图像内容。
- 中列灰色斜线：这一步没有读取这个视觉 key，不能把它当成低注意力。
- 右列灰色斜线：原始 VV 掩码禁止种子关联此处，不是“模型认为未来不重要”。
- 大块浅灰文字框：这一去噪步没有运行探针，因此没有这张热力图。
- 绿色 `+`：本步实际重算了该视觉 query；不是动作 query `q0`。
- 青色圆圈：AV 选出的种子；不是最终全部读 key 或重算 query。
- 第 0 步是 Dense，所以全部位置都读、都重算是预期行为。

AV 图汇总所有注意力头和动作 token。AV 保留联合 `[V,A]` softmax 的原始
概率，VV 使用独立色标；跨图比较要看色条数字，不能只比颜色亮暗。
首帧中 `+` 集中在前几个格子，可能来自每帧配额与零漂移分数的稳定并列排序，
不能据此说这些格子最重要。

## 怎么和 M1、M3 对上

图标题写出 M1 档位、**单次 Sparse** 的 Q/KV 配额，以及整个 chunk 的总 Q 上限。
例如低档上限 324 行 = 首步 Dense 的 294 行 + 最多 30 行额外重算。
低档四格图只展示首帧的 10 个绿色 `+`；另外 20 个分在两个未来 latent 帧上，
要到九格图的后两行看。30 是三帧合计，不能只数真实首帧里的符号。
总预算限制的是视觉 query 行数，不能直接当成 FLOP 或时间加速比。

`m1-m3-budget-ledger.png` 是执行账本：每行一个去噪步，每列一个视觉 token；
绿色代表该步真的重算。实际路由决定截图位置，本轮导读包含 Dense 步 0、
实际 Sparse 步 3 和末步 9。每步仍计算动作分支，视觉缓存只在同一 chunk 内复用。

这些图来自独立的开发观测轨迹（init 1），不是五对 SR 测试（init 0）的截图。
它们证明输入、预算、注意力和执行可以追踪；不能单独解释某个 SR 成败的原因，
也不能证明 AV/VV 选取优于其他方法。每个目录的 `render.json`、源 `trace.json`
和 `tensors.npz` 保留源码、输入、字体与张量哈希及真实执行记录。
